## [지시문] — 복사 시작

당신은 시스템 아키텍트입니다. **대지나염(JHproject)** 단체티·나염 커스텀 쇼핑몰의 **아키텍처 설계서**를 작성하세요.

### 입력 근거
- 사용자가 붙인 프로젝트 설명·기술스택·폴더 구조만 사실로 사용한다.
- 추측은 **「(가정)」** 표시. 모르는 인프라 IP/도메인은 `〔미기재〕`로 둔다.
- DB 상세는 `테이블정의서`가 있으면 참조하되, 본 문서는 **아키텍처 관점**만.

### 출력 언어·형식
- **한국어**, SI 제출용 톤.
- **Word에 붙여넣기 좋게**: 장(1., 2., …) / 절(1.1) / 불릿.
- **Mermaid**는 논리·배포·주문 흐름 3개만 (코드블록 허용).
- 표지·승인란은 5줄 이내 텍스트만.

  - API: `src/app/api/**/route.ts`

- 4.2 **논리 구성도** (Mermaid `flowchart TB` 또는 계층 박스 설명)

**5. 물리 아키텍처**

- 5.5 외부 연동 (토스페이먼츠, Google/Kakao OAuth, 〔이메일〕)

**6. 기술 스택**
- 6.1 표: 구분 / 제품·버전 / 용도  
  - Next.js 16, React 19, TS, Tailwind 4, Zustand, Fabric.js, Three/R3F(3D 미리보기), Prisma 6, MySQL, jose/JWT, bcrypt, Toss SDK, PM2  
- 6.2 선정 사유 (1~2문장/주요 항목)

**7. 애플리케이션 아키텍처 (Next.js App Router)**
- 7.1 라우팅 구조 (`/`, `/products`, `/builder`, `/admin`, `/api`)  
- 7.2 Server vs Client Component 역할 구분 원칙  
- 7.3 상태 관리 (빌더: Zustand + localStorage persist)  
- 7.4 주요 사용자 흐름 3종 + **시퀀스(Mermaid sequenceDiagram)**  
  - (1) 커스텀: 상품 → 빌더 → 주문 → 결제  
  - (2) 기성품: 상품 → 장바구니 → 주문  
  - (3) 관리자: 로그인 → 주문 상태·배송

**8. API 아키텍처**

- 8.3 인증: JWT 쿠키, `requireUser` / `requireAdmin`

**9. 데이터 아키텍처**
