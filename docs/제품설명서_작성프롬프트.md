# 제품설명서 — 작성 프롬프트

**용도:** ChatGPT, Claude, Gemini 등에 붙여 **A4 인쇄용 HTML 웹문서**로 제품설명서 전체를 생성한다.  
**이 파일만** 붙여도 초안이 나오게 사실 시트를 넣었다.  
코드·매뉴얼을 함께 붙이면 그 내용을 **사실 시트보다 우선**한다.

권장 첨부(있으면): `README.md`, `docs/대지나염_사용자·운영_매뉴얼.md`, `docs/테이블정의서.md`의 개요·Enum·테이블 목록.

## [지시문] — 여기부터 복사

당신은 소프트웨어 제품 문서 작성자입니다. 아래 **사실 시트**만 근거로, 단체복 나염 커스텀 커머스 플랫폼의 **제품설명서**를 한국어로 완성하세요.

### 이 문서의 성격

- **제품설명서**다. 투자 설득(IR)이 아니고, 버튼 단위 사용자 매뉴얼도 아니다.
- 독자: 도입 검토자, 운영 총괄, 외주·검수, 내부 기획.
- 답할 질문: 이 제품이 무엇인지, 누가 쓰는지, 모듈이 무엇인지, 주문 한 건이 어떻게 끝나는지, 규칙과 한계는 무엇인지.
- 분량: A4 본문 **25~40쪽**에 해당하는 깊이. 목차만 주고 끝내지 말 것. 각 절은 문단 + 필요 시 표.
- **산출물:** 브라우저에서 열고 인쇄(PDF 저장)하면 A4로 떨어지는 **단일 HTML 파일**. 마크다운·Word 본문으로 출력하지 말 것.

### 절대 규칙

1. 사실 시트(또는 첨부 코드/문서)에 없는 기능·수치·일정·매출을 **만들지 말 것**. 모르면 `〔미기재〕` 또는 「운영 정책에 따름」.
2. **특정 판매 상품명·브랜드 SKU**(예: 보아티, TOMS 모델코드, 현재 몰에 올라온 티셔츠 이름)를 제품 기능처럼 쓰지 말 것. 상품은 `CUSTOM`(커스텀) / `READYMADE`(기성품) 유형으로만 설명한다.
3. 고객이 보는 **몰 브랜드명**(헤더 로고, 사이트 설정의 브랜드명)과 **본 소프트웨어 제품**을 분리한다. 제품설명서의 제품명은 「대지나염 단체복 나염 커스텀 커머스 플랫폼」(이하 본 시스템)이다.
4. 영어 모듈명(Storefront, Order OS 등)을 쓰지 말 것. 모듈 이름은 아래 5개 한글명으로 고정.
5. 「필수 모듈 / 선택 모듈」 구분을 쓰지 말 것. 다섯 모듈은 모두 기본 제공이다.
6. README에 **개발중**으로 적힌 항목은 제공 기능처럼 단정하지 말고 「제공 범위 / 제한」에 분리한다.
7. 클릭 순서(「로그인 버튼을 누른다」)는 쓰지 말 것. 규칙·결과·상태만 쓴다. 화면 설명은 맵·역할 + **아래 이미지 자리**로 처리한다.
8. API 전체 목록, DB 컬럼 전부, 소스 경로 나열은 하지 말 것. 필요하면 부록에 도메인만.
9. 출력은 **완전한 HTML 문서 하나**(`<!DOCTYPE html>`부터 `</html>`까지). 장/절 번호는 아래 목차와 동일하게 고정. 앞뒤에 설명 문장·마크다운 펜스를 붙이지 말 것.
10. 추측은 본문에 섞지 말고 `(가정)` 표시. 가정은 최소화.
11. **실제 스크린샷·도식을 생성하지 말 것.** 가짜 `<img>`, ASCII 와이어프레임, “여기에 그림” 한 줄짜리 메모는 금지. 대신 아래 **이미지 자리 HTML**을 본문에 넣어 캡처로 교체할 공간을 확보한다.

### 출력 형식: A4 HTML 웹문서

한 파일로 끝낸다. 외부 CSS/JS CDN, 추적 스크립트, 프레임워크 금지. `<style>`은 `<head>`에만.

**페이지**
- `@page { size: A4; margin: 18mm 16mm 20mm; }`
- 화면에서도 A4처럼 보이게: `body` 배경 `#e8e8e8`, 본문은 `.page-sheet` 또는 `main.doc`를 `width: 210mm`, 흰 배경, 가운데 정렬, 그림자. 인쇄 시 그림자·회색 배경 제거.
- 본문 폭은 A4 안쪽(약 178mm). 글자 크기 10.5~11pt, 제목은 계층만 키운다.
- 한글: `"Pretendard", "Noto Sans KR", "Malgun Gothic", sans-serif` (웹폰트 URL은 넣지 말고 시스템/로컬 폴백).
- 색: 본문 `#171717`, 제목 `#111`, 선 `#d4d4d4`, 표 헤더 `#f4f4f5`. 원색 마케팅 테마 금지.
- 표: `width:100%`, 테두리, 행 나눔, `page-break-inside: avoid` 가능한 범위에서.
- 제목 앞 `page-break-before`는 장(`h1`)만. 절이 페이지 맨 아래에 홀로 남지 않게 `h2, h3, table, figure { break-inside: avoid; }` 정도.

**문서 뼈대**
- `lang="ko"`
- `<title>`: 대지나염 단체복 나염 커스텀 커머스 플랫폼 — 제품설명서
- 표지 블록(첫 A4): 문서명, 제품명, 버전, 작성일, 독자
- 이어서 목차(`nav#toc` + 앵커)
- 본문 `main` 안에 1~12장
- 쪽 머리글/바닥글은 print용으로 `position` 또는 `@page` 수준. 브라우저 한계가 있으면 표지·목차에만 문서 정보, 본문 하단에 「제품설명서 · 대지나염」 작은 문구.

**인쇄**
- `@media print`에서 `.page-sheet` 폭 100%, 여백 0, 박스섀도 없음, 배경 흰색.
- `a[href]::after { content: none; }` (URL 펼침 금지)

**Mermaid**
- CDN mermaid.js를 불러오지 말 것. 구성도·흐름은 HTML+CSS 상자 다이어그램 또는 `<pre class="diagram">` 텍스트 상자로. 인쇄가 깨지는 SVG 생성 스크립트 금지.

### 이미지 자리 확보

화면을 보면 이해가 빨라지는 지점마다 자리를 비워 둔다. 본문만으로 충분한 표·상태 설명에는 억지로 넣지 않는다.

**블록 형식 (이 HTML을 반복, 내용만 바꿈)**

```html
<figure class="fig-slot fig-slot--full" data-fig="n-m">
  <div class="fig-slot__box" style="aspect-ratio: 16 / 9;">
    <span class="fig-slot__hint">그림 n-m · 스크린샷을 이 영역에 넣을 것</span>
  </div>
  <figcaption>
    <strong>그림 n-m.</strong> (캡션)
    <span class="fig-slot__shot">촬영: (경로·화면·상태)</span>
  </figcaption>
</figure>
```

CSS 요지:
- `.fig-slot--full` 가로 100%, `.fig-slot--half`는 2열(인쇄 시에도 가능한 한 나란히, 좁으면 세로로).
- `.fig-slot__box`는 점선 테두리, 연한 회색 배경, 최소 높이 전폭 **72mm**, 절반 **48mm**. 안의 `hint`만 허용. 본문 문장을 상자 안에 넣지 말 것.
- `figcaption`은 상자 아래 9pt.

- 번호는 장 기준 연속. 예: 그림 2-1, 그림 4-1.
- 크기는 `가로 전폭`(핵심 화면) 또는 `가로 절반`(보조·대비 2장)만 쓴다. 전폭은 빈 상자 높이 **8~10줄**, 절반은 **5~6줄**.
- 캡션은 기능 이름이 아니라 **그 그림이 증명하는 것**. 예: 「상품 상세에 임베드된 시안 주문 화면」.
- 촬영 대상에 경로를 적는다. 예: `/products/{slug}` 커스텀 상품, 로그인 회원.
- 몰에 올라온 **특정 SKU·상품명이 찍히지 않게** 촬영 안내에 「상품명은 가려도 됨」을 필요할 때만 적는다.
- 구성도·흐름도는 HTML 상자 다이어그램 1개씩. 그 바로 아래에 스크린샷 자리를 중복하지 않는다.

**7장 화면 맵**은 트리 표 + 해당 경로의 그림 자리만. 「스크린샷을 나중에 넣으시오」라는 지시 문장만 남기지 말 것. 빈 상자가 곧 지시이다.

### 어조

- 단정하고 짧게. 마케팅 문장(혁신, 올인원, 업계 최초) 금지.
- 한 기능은 「무엇을 입력하면 무엇이 남는가」로 쓴다.
- 표는 역할·상태·규칙에 쓰고, 기능 자랑 나열에 쓰지 않는다.

### 사실 시트 (프로젝트 근거)

**식별**
- 프로젝트: JHproject / 대지나염
- 한 줄 정의: 단체티·유니폼 나염을 위해, 상품 선택 → 시안 편집 → 수량 견적 → 주문·결제 → 제작·출고·CS를 한 웹 시스템으로 묶은 커스텀 커머스.
- 범용 오픈마켓/카페24 테마가 아니다. 상품마다 앞·뒷면 목업과 인쇄영역, 수량 구간 단가, 제작 상태 머신이 붙어 있다.
- 핵심 루프는 동작: 홈 → 상품 → 빌더 → 주문 → 관리자 처리.
- 개발중(운영 마무리): 토스페이먼츠 실키·실결제, 이메일/알림(현재 로그 스텁), 업로드를 클라우드로 이전, 모바일 QA·카피 폴리싱.

**기술 (설명서에는 환경 장에서만 짧게)**
- Next.js 16 App Router, React 19, TypeScript, Tailwind CSS 4
- 시안 캔버스: Fabric.js 7 + Zustand
- 3D 스핀 미리보기: Three.js / React Three Fiber
- DB: MySQL + Prisma 6, 물리 테이블 약 30개
- 인증: JWT 쿠키, bcrypt, 카카오·구글 OAuth
- 결제: 토스페이먼츠 SDK 준비 + 무통장 입금
- 배포: PM2, `next start` (대표적으로 EC2)
- 파일: 현재 `public/uploads` 로컬 저장. 디자인 업로드·관리자 목업 업로드 파일당 8MB, PNG/JPG/WEBP
- AI 시안: OpenAI 이미지 API (`gpt-image-1` 기본), 키 없으면 사용 불가 안내. 로컬 엠블럼 생성 폴백 있음. 상표·캐릭터 프롬프트 차단. 참조 이미지 최대 3장, 장당 4MB. 로그인 필수. 레이트 리밋 있음.

**역할**
- 비회원: 빌더 시안, 이메일 필수 주문, 주문번호+이메일 조회. 체크아웃(결제 페이지)은 로그인 필요.
- 회원(CUSTOMER): 이메일 가입(인증 토큰), 카카오/구글, 시안 저장, 기성품 장바구니·찜, 쿠폰·포인트, 마이페이지, AI 시안, 서버에 큰 디자인 이미지 저장
- 관리자(ADMIN): `/admin/login` 전용. 일반 `/login`과 분리. 고객 결제 화면 진입 시 관리자 주문으로 보냄.

**판매 유형**
- CUSTOM: 상품 상세에 빌더가 임베드됨. 시안 후 바로 주문. 장바구니 없음(장바구니는 기성품 전용).
- READYMADE: 옵션·수량 후 장바구니/바로구매.

**모듈 5개 (이 이름으로만 구성도를 그릴 것)**

1. **시안 주문**  
   앞·뒷면 독립 시안, 인쇄영역 가이드, 이미지·텍스트 레이어, 실행취소, 템플릿(2분컷), AI 로고·엠블럼, 360° 스핀 미리보기, 수량·사이즈·색·인쇄면 등 옵션, 실시간 견적, 시안 JSON이 주문에 결합.  
   작업 요청(캔버스 핀·메모)은 **주문 전에도** 시안에 남길 수 있고 주문 저장 시 함께 간다.  
   상품 상세 임베드 빌더와 독립 `/builder`·주문 상세 빌더가 같은 엔진이다.

2. **상점·카탈로그**  
   홈(히어로 캐러셀, 원형 메뉴, 기획전, 아이디어·가이드 카드), 카테고리 목록, 상품 상세, 검색, 찜, 기성품 장바구니, 배너·팝업·콘텐츠 글 CMS.  
   관리자가 상품에 목업 면(앞/뒤 이미지, 해상도, 인쇄영역 비율 0~1), 상세 섹션(스토리·안내·사이즈·FAQ 등), 수량 할인 구간을 등록하면 상점과 시안 주문이 같은 상품을 본다.

3. **주문·결제**  
   경로: 빌더 주문 / 기성품 바로구매 / 장바구니 일괄 / 비회원 기성 주문.  
   결제: 카드·간편결제(토스), 무통장.  
   쿠폰·포인트는 **결제 직전** checkout에서 적용. 수량 구간 단가, 배송비·무료배송 기준은 상품·사이트 설정.  
   주문 상태와 결제 상태를 분리. 무통장은 관리자 입금 확인 전까지 미입금이며 그 전 제작 착수하지 않는 것이 운영 전제.

4. **제작·출고**  
   관리자 대시보드 할 일: 입금 확인 필요, 제작 착수 대기, 송장 미입력.  
   주문 상태 전이, 송장 입력, 작업 핀, 주문 코멘트 스레드, 아트워크·빌더 JSON 전달, 관리자 빌더에서 시안 수정(`from=admin`).  
   Comment(운영자↔고객 대화)는 **주문 ID가 생긴 뒤**에만 동작.

5. **고객·CS**  
   마이페이지(주문, 찜, 쿠폰, 교환반품, 프로필, 배송지), 비회원 주문조회 `/orders`, FAQ, 1:1 문의, 우하단 FAQ 기반 챗봇, 상품 리뷰, 교환·반품 신청.  
   고객 취소: 대기 또는 입금대기이고 **결제 완료 전**만. 이후는 관리자·CS.

**주문 상태 (OrderStatus)**  
PENDING 대기 / AWAITING_PAYMENT 입금대기 / CONFIRMED 확인됨(결제 확인·제작 대기) / IN_PRODUCTION 제작 중 / SHIPPED 배송 중 / DELIVERED 배송 완료 / CANCELLED 취소

**결제 상태 (PaymentStatus)**  
UNPAID 미입금 / PAID 입금완료 / REFUNDED 환불 / FAILED 실패

**결제 수단 (PaymentMethod)**  
CARD / BANK_TRANSFER / VIRTUAL_ACCOUNT(스키마상 존재)

**관리자 메뉴**
- 개요: 대시보드
- 주문: 주문 목록, 교환반품, 매출
- 상품: 카테고리, 상품, 컬렉션
- 마케팅: 배너(히어로/프로모/아이디어/가이드/원형메뉴), 팝업, 소개글, 쿠폰
- 고객: 리뷰, 문의, 계정
- 시스템: 설정(브랜드명, 사업자, CS 연락처, 무통장 계좌, 배송비·무료배송 기준 등). 저장 시 스토어프론트·푸터·checkout에 반영.

**주요 고객 경로**
- `/` 홈, `/products/list`, `/products/{slug}` 상세(커스텀이면 임베드 빌더), `/builder`, `/templates`, `/cart`, `/checkout/{orderId}`, `/checkout/success`, `/checkout/fail`
- `/login` `/register` `/mypage` `/mypage/orders/{id}` `/mypage/wishlist` `/mypage/coupons` `/mypage/returns` `/mypage/addresses` `/mypage/profile`
- `/orders` 비회원 조회, `/inquiry`, `/faq`, `/returns`, `/ideas/{slug}`, `/guides/{slug}`
- `/admin/login`, `/admin` 및 하위

**가격**
- 상품 기본가 + 옵션 + 수량 할인 규칙(`quantity_discount_rules`) + 배송비 − 쿠폰·포인트
- 빌더 우측 패널에서 옵션 변경 시 금액 실시간 갱신

**데이터 도메인 (설명서에 테이블명 나열은 부록 수준만)**  
회원·인증, 포인트·쿠폰, 장바구니·찜, 카탈로그(카테고리·상품·목업면·상세섹션·이미지·컬렉션·수량할인·디자인템플릿), 리뷰, 배너·팝업·콘텐츠·사이트설정, 디자인(시안), 주문·품목·코멘트·결제, 문의, 반품

**명시적으로 없는 것 (있다고 쓰지 말 것)**

## 사용 방법

1. 위 「복사」 구간 전체를 대상 AI에 붙여넣는다.  
2. 가능하면 이어서 아래를 붙인다.

```
추가 근거: (README / 매뉴얼 / 테이블정의서 텍스트)
작성일: YYYY-MM-DD
버전: 1.0
회사·작성자: 〔미기재〕 또는 실제 값
```

3. 나온 HTML을 `.html`로 저장해 브라우저에서 연다. A4 맞춤은 인쇄 미리보기(용지 A4)로 확인한다.  
4. `.fig-slot__box` 안에 실제 스크린샷을 넣는다(`<img>`로 교체). 캡션은 `figcaption`을 유지한다.  
5. 인쇄 → PDF로 저장하면 A4 제품설명서가 된다.
